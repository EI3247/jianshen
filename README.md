# 健身记录 · jianshen

一个自己用的健身记录应用 —— 按训练周期铺日历、点开当天逐组记重量×次数、记身体围度和饮食、看趋势。

手机浏览器打开后「添加到主屏幕」，全屏无地址栏，和原生 App 一样用。

**零第三方依赖**：后端一个 Python 文件（只用标准库 `http.server` + `sqlite3`），前端一个 HTML 文件（原生 JS，没有构建步骤）。
`git clone` 之后一条 `docker compose up -d` 就能跑，不用装任何包。

---

## 功能

### 训练

- **训练计划**：按「部位 → 动作 → 组数 × 次数」三层搭建，动作可选**力量**或**有氧**（有氧记时长和最高心率）
- **日历**：计划按周期严格铺满日历，训练日和休息日都占位；点开当天就用计时器逐组记录
- **灵活调整**：练不了可以「今天休息」（计划整体顺延），想加练可以「改锻炼日」（计划整体提前）
- **计划复制**：把一个成员的计划整套复制给另一个成员
- **训练状态**：每次训练记一下 `很好 / 一般 / 疲惫 / 不适`

### 身体与饮食

- **身体围度**：体重、体脂、胸围、腰围、臀围、臂围、肩宽，只记你关心的项，表格展示带环比变化
- **热量收支**：基础代谢 ＋ 日常活动 ＋ 力量训练 ＋ 有氧 = 总消耗，和当天摄入对上
  - 基础代谢支持 Katch-McArdle（按体脂算）/ Mifflin-St Jeor / 粗略估算，也可以直接填自定义值
  - 训练消耗按 `(MET − 1) × 体重 × 时长` 计净消耗，有氧按项目 MET 分别计算
- **记饮食**：按次记（热量 / 蛋白），自动累加当天总量，记错可以单条删改
- **预设模板**：常吃的东西存成模板，一点就填
- **目标管理**：训练日 / 休息日的蛋白（g/kg）和热量目标分开设置，达标 / 不足 / 过量实时提示

### 统计

本周训练量（次数/组数/容量/时长，带环比）、动作最大重量 PR 榜（含 Epley 估算 1RM）、热量收支趋势、体重体脂曲线。

### AI 问答（可选，不配也能用）

接任意 **OpenAI 兼容**接口（DeepSeek、智谱、通义、Kimi、火山、OpenRouter、Ollama、vLLM、各类中转网关都行）。

在「记一笔」下面问一句「一碗红烧肉」，AI 把热量和蛋白**填进表单**，你确认无误再点记一笔。

> AI 只负责填表，不自动记账 —— 模型估热量误差不小，得人工过一眼。

### 数据导出

全量 JSON（可按成员或全员）+ 训练 / 身体 / 饮食 CSV。

> 访问密码和 AI 的 API key **不会**被导出。

## 快速开始

```bash
git clone https://github.com/EI3247/jianshen.git
cd jianshen
docker compose up -d
```

打开 `http://localhost:8091`。

**密码怎么来**：没有通过环境变量指定时，首次启动会随机生成一个密码，打印在容器日志里：

```bash
docker compose logs | grep -E "访问密码|管理密码"
```

密码存在数据库里，重启不会变。想自己指定就用下面的环境变量。

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `ACCESS_PASSWORD` | 首次启动随机生成 | 访问密码 |
| `SUPER_PASSWORD` | 首次启动随机生成 | 管理密码（成员管理 / 改密码 / 导出 / 清空数据时需要） |
| `PORT` | `8091` | 监听端口 |
| `DATA_DIR` | `/data` | 数据库目录 |

在 `docker-compose.yml` 同级建一个 `.env` 文件即可覆盖：

```env
ACCESS_PASSWORD=你的密码
SUPER_PASSWORD=你的管理密码
```

> **放到公网之前务必自己指定一组密码**，本项目按「家庭内网自用」设计，没有账号体系和 HTTPS，直接暴露公网不安全。

## 数据与备份

数据是一个 SQLite 文件，在 `data/jianshen.db`（WAL 模式）。

**备份别直接拷 `.db` 文件** —— WAL 模式下可能有一部分数据还在 `-wal` 里没落盘，直接拷会丢数据。用这个：

```bash
# 在宿主机上（推荐，在线安全，不用停容器）
sqlite3 data/jianshen.db ".backup 'backup/jianshen.db.$(date +%m%d_%H%M)'"
```

程序每次启动会自动做一次 WAL checkpoint，所以 `-wal` 文件不会无限增长。

恢复就是拿备份文件覆盖 `data/jianshen.db`（顺便删掉同目录的 `-wal` / `-shm`），然后重启容器。

## 一些设计取舍

- **零依赖**：只用 Python 标准库，不装任何 pip 包。代价是没上 Web 框架，路由是自己写的一串 `if path == ...`。好处是十年后 `docker compose up` 还能跑。
- **单文件前端**：没有打包、没有 node_modules，改完刷新页面就生效。
- **AI 只填表不记账**：见上文。
- **没有多账号隔离**：一套密码登录，顶部下拉切换成员，成员之间数据独立但互相可见。定位是家庭/小圈子自用，不是多租户服务。
- **密码以明文存在数据库里**：本地自用场景，省掉哈希和加盐的复杂度；如果要多用户部署，这里需要改。
